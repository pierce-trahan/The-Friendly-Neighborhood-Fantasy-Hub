# V1.0.2 Corrective Specification: Market Board and Mock CPU

**Status:** Complete

**Date:** 2026-08-03

## Problem

The Phase 4 engine used the frozen Personal Board as every CPU manager's value
baseline. Players absent from that board were deliberately ordered by name as a
stable fallback. Once V1.0.1 began loading the complete player universe, a board
with one ranked player caused the remaining CPU selections to follow the
alphabetical fallback. The result was deterministic and auditable, but not a
credible practice draft.

## Corrective Outcome

New mock sessions use a separate, bundled market baseline for CPU valuation.
The user's Personal Board remains authoritative for the user's views,
evaluations, notes, and manual decisions. Market evidence informs simulated CPU
behavior only and is never presented as objective player quality.

## Approved Source

The initial offline snapshot is a transformed subset of DynastyProcess's open
fantasy-football data repository:

- upstream file: `files/values.csv`;
- underlying signal: FantasyPros dynasty expert consensus ranking;
- selected field: `ecr_2qb`, used as a Superflex-compatible proxy;
- snapshot date: recorded from the source rows;
- repository license: GPL-3.0, preserved in the data artifact's provenance;
- refresh: deliberate release-time transformation, never a draft-time network
  request.

This is expert consensus rank (ECR), not average draft position (ADP). It does
not include an ADP mean, variance, completed-draft sample size, or an explicit
tight-end-premium adjustment. The interface must say so.

## Frozen Data Contract

At mock creation the application:

1. loads and validates the bundled snapshot;
2. matches candidates conservatively by normalized name and position;
3. saves each matched candidate's integer market order on the draft snapshot;
4. saves source, date, format, coverage, and limitation metadata on the mock;
5. includes the market order and provenance in the deterministic content
   fingerprint; and
6. performs no network request.

An existing mock keeps its original engine version and frozen evidence. A new
snapshot affects only newly created mocks.

## CPU Ordering and Fallbacks

For `market-board-v1`, CPU baseline order is:

1. matched dynasty 2QB ECR order;
2. unmatched personally ranked candidates, in Personal Board order;
3. unmatched candidates in a deterministic, position-aware fallback order;
4. normalized name and canonical player ID only as final tie-breakers.

Roster needs, CPU archetype, duplication penalties, and seeded variation remain
bounded Phase 4 score components. The market order is the dominant component,
but no strategy or profile imposes a hard position lock.

If the bundled market artifact is missing or invalid, mock creation remains
available through the old `practice-board-v1` engine. The response visibly
labels the market baseline unavailable and restores the prior Personal Board
fallback rather than silently claiming market evidence.

## API and Interface Contract

Each mock response exposes a `market_baseline` object containing:

- label and evidence kind;
- source name and source URL;
- rank type and league-format proxy;
- source date and freshness state;
- matched and total candidate counts;
- coverage percentage;
- confidence; and
- plain limitation codes.

Saved CPU decision reasons use `MARKET_ECR_BASELINE` when market evidence was
used and `PRACTICE_BOARD_BASELINE` only for the explicit fallback engine.

## Acceptance Tests

1. A board containing only Bijan Robinson still produces plausible market-led
   CPU selections from the bundled player universe rather than alphabetical
   names.
2. The same candidates, league shape, profiles, seed, randomness, engine
   version, and market snapshot reproduce the same picks after restart.
3. Market rank is frozen per draft candidate and survives source-file changes.
4. Personal Board order remains unchanged and remains the user's visible
   authority.
5. Source name, date, ECR label, coverage, and limitations are visible before
   or during the mock.
6. Missing or invalid market data degrades visibly to the old practice-board
   engine without blocking mock creation.
7. Alphabetical ordering is used only after market, personal, and
   position-aware fallback keys.
8. Existing Phase 4 correction, undo, recovery, one-pick transaction, and
   deterministic audit tests continue to pass.
9. The complete workflow works offline from a fresh local data directory.

## Explicit Deferrals

- platform-wide Sleeper ADP;
- scraping completed public drafts;
- an ADP distribution or availability-probability model;
- live market refresh during a draft;
- provider credentials or paid APIs;
- a universal baseline shared across incompatible 1QB, Superflex, redraft, and
  tight-end-premium formats; and
- automated picks for the user's slot.
